# 2026-05-05 — niyama v0.9.0 P(-1) Security Audit

**Auditor**: Claude (Opus 4.7) — under user direction.
**Scope**: niyama v0.8.0 source as of commit immediately preceding
the v0.9.0 hardening pass. All 5 engines (bre, re2, pcre, fuzzy,
vim) plus the shared modules `src/posix_classes.cyr` and
`src/unicode_props.cyr`.
**Methodology**: per
[CLAUDE.md § Security Hardening](../../CLAUDE.md#security-hardening-before-every-release)
and [first-party-standards § Security Hardening](https://github.com/MacCracken/agnosticos/blob/main/docs/development/applications/first-party-standards.md#security-hardening-new--required-before-every-release).
8 mandatory items walked; findings tagged
**CRITICAL** / **HIGH** / **MEDIUM** / **LOW**.

Internal-review findings (gaps, parallel codepaths, test coverage)
live in `docs/development/v0.9.0-review-findings.md` — this audit
focuses on the security-specific subset.

---

## Headline

**No CRITICAL or HIGH findings.** Two MEDIUM items affect security
posture (test coverage gaps, not exploitable-as-shipped). Two LOW
items are documentation completeness. No exploits or
known-CVE-class vulnerabilities identified.

niyama's design choices that materially limit attack surface:

- **Interpreter-only — no JIT.** Avoids the entire JIT-memory-bypass
  CVE class (CVE-2019-20454 et al.).
- **No filesystem touch.** Avoids path-traversal entirely.
- **No subprocess execution.** Avoids command-injection entirely.
- **Layered backtracking guards.** pcre has both step-limit
  (default 1M) and depth-limit (256) — independent ceilings.
- **Linear-time engines (re2/bre/vim) structurally cannot
  catastrophic-backtrack.** Pike NFA queue dedup precludes
  exponential-time matching on adversarial patterns.

## 1. Input validation

**Status**: PASS

Every public `niyama_<engine>_compile()` / `_match()` / `_search()`
/ `_search_at()` validates inputs at entry. Sample audit:

| Entry point | Input | Validation |
|-------------|-------|------------|
| `niyama_pcre_compile(pat)` | `pat` (cstring) | `strlen(pat)` followed by `if (n > PCRE_MAX_INSTRS)`-equivalent check via per-emit `_pcre_emit_raw` `instr_n >= MAX_INSTRS` bound. |
| `niyama_re2_match(nfa, s)` | `nfa`, `s` | `if (nfa == 0) { return 0; }` upstream of any deref. `s` len via `strlen`. |
| `niyama_fuzzy_compile_opts(pat, max_edits, flags)` | `pat`, `max_edits` | `if (max_edits < 0) { return 0; }`, `if (n > FUZZY_MAX_PAT_LEN) { return 0; }`. |
| `niyama_*_search_at(nfa, s, len, from)` | All four | `if (nfa == 0)`, `if (from > len)` checks present. |

Error paths return cleanly via `_<engine>_last_error()` accessors;
no partial-state-on-error issues observed.

**No findings.**

## 2. Buffer safety

**Status**: PASS with one MEDIUM note

`var buf[N]` declarations across the engines all sized in **bytes**
per the Cyrius convention (CLAUDE.md § Key Principles). Sample
audit:

- `RE2_NFA_HEADER_SIZE = 256` — header fixed-size, all offsets
  bounds-checked. ✓
- `PCRE_MAX_INSTRS * 16` (= 65 536 bytes) — instruction buffer.
  Index bounded by `_pcre_instr_n < PCRE_MAX_INSTRS` at every
  emit. ✓
- `MAX_CLASSES * 32` (= 2 048 bytes) — class bitmap table. Per-byte
  access at `class_base + ci * 32 + (c >> 3)`; `c >> 3` ≤ 31 for
  c ≤ 255. ✓
- `MAX_SAVES * 8` (= 160 bytes) — save array. Index `idx * 8` for
  idx ≤ MAX_SAVES-1 = 19. ✓
- `RE2_NAME_SLOT_SIZE = 40`, `MAX_NAMES = 9` — name table 360 bytes.
  Slot writes at `dst + name_len` for `name_len ≤ NAME_MAX_LEN = 31`. ✓

**MEDIUM finding (B4 from internal review)** — `_pcre_match_run`
calls `alloc(PCRE_MAX_SAVES * 8)` (160 bytes) inside the matcher
loop at 6 sites: SPLIT, LOOKAHEAD, NLOOKAHEAD, LOOKBEHIND, RECURSE,
plus top-level entry. Not unsafe (bump allocator, finite per
match invocation), but for long-running consumers (cyim editing a
large file) the allocations accumulate. Bench in step 7; if
measurable, refactor to a depth-indexed pool.

**No CRITICAL / HIGH buffer findings.**

## 3. Syscall review

**Status**: PASS

niyama's syscall surface is intentionally tiny:

- `syscall(1, 1, "...", N)` in `src/main.cyr` — sole-purpose smoke
  banner write. Hardcoded buffer + length. ✓
- `syscall(60, exit_code)` — process exit. ✓
- All other syscalls are stdlib-mediated (`alloc`, `strlen`, etc.).
  Stdlib audit is the cyrius project's responsibility, not niyama's.

niyama does **not** call `read`, `write`, `open`, `close`,
`mmap`, `fork`, `exec*`, `socket`, or any privileged syscall
directly. There's no filesystem touch, no network touch, no
process spawn.

**No findings.**

## 4. Pointer validation

**Status**: PASS

Spot-audited every `load8` / `load64` / `store8` / `store64`
against pattern or input pointers:

- **Pattern pointer**: every `load8(_<engine>_pat + _pos)` is
  upstream-guarded by `if (_pos < _pat_len)`. Verified at the
  entry of each parser top-level function (`_parse_alt`,
  `_parse_concat`, `_parse_atom`, `_parse_primary`).
- **Input pointer**: every `load8(input + pos)` is
  upstream-guarded by `if (pos < input_len)`. The codepoint-stepped
  loops (re2, vim) check `if (pos < input_len)` at the top of
  each outer iteration; the byte-stepped loop (pcre) checks
  `if (pos >= input_len) { return 0 - 1; }` at every consume-op.
- **NFA / handle pointer**: every public API entry has
  `if (nfa == 0) { return ...; }` (or `if (h == 0)` for fuzzy).
- **Class table pointer**: `class_base + ci * 32 + (c >> 3)` —
  `ci` bounded by `_<engine>_class_n` (≤ MAX_CLASSES); `c >> 3` ≤
  31. ✓
- **Save array pointer**: `saves + idx * 8` — `idx` packed as
  `(opcode >> 8) & 0xFF`; `idx ≤ MAX_SAVES * 2 - 1`. ✓
- **stdlib `_uc_decode_utf8` / `unicode_category` /
  `unicode_to_lower` / `str_normalize`** — these are stdlib
  responsibilities; niyama-side audit is "we pass valid args"
  (verified by typed pointer chain).

**No findings.**

## 7. Known-CVE review (PCRE2 corpus)

**Status**: PASS — all canonical PCRE / PCRE2 CVE patterns defended

(Detail in `docs/development/v0.9.0-review-findings.md` § G1.)

| CVE class | niyama defense |
|-----------|----------------|
| CVE-2015-2326 (lookbehind width OOB) | `_pcre_compute_width` is conservative — sums known widths only, rejects unknown opcodes with `-1`. |
| CVE-2017-7186 (UTF-8 + grapheme OOB) | `_uc_decode_utf8` returns 0xFFFD step=1 on truncation; matchers handle. No `\X` operation. |
| CVE-2017-11164 (recursion limit) | `_pcre_depth_limit = 256` + `_pcre_step_count` step ceiling. Both fire independently. |
| CVE-2016-3191 (backref + case-fold OOB) | niyama backref is byte-compare (1:1), no length change. |
| CVE-2014-9769 (named group MAX_NAME_SIZE) | `PCRE_NAME_MAX_LEN = 31` checked in `_pcre_add_name`. |
| CVE-2015-3217 (`(?R)` infinite recursion) | step-count + depth bounds; anchored body stops self-recursion at non-zero pos. |
| CVE-2019-20454 et al. (JIT bypass) | N/A — interpreter-only. |

**MEDIUM finding (C3 from internal review)**: fuzz harnesses
generate random *patterns* but don't exercise random / deliberately
malformed *input strings*. Given the v0.8.0 codepoint-stepping
additions decode UTF-8 in input, fuzz coverage of invalid-UTF-8
input is a real gap. Step 6 adds invalid-UTF-8 fuzz seeds (lone
continuation bytes, truncated multi-byte sequences, overlong
encodings, lone surrogates expressed as 4-byte UTF-8).

**No CRITICAL / HIGH findings.**

## 8. Boundary / limit testing

**Status**: PASS with one MEDIUM note

The frozen contract includes these limits:

- `MAX_INSTRS = 4096` (all four regex engines)
- `MAX_CLASSES = 64`
- `MAX_SAVES = 20`
- `MAX_NAMES = 9` (re2, pcre)
- `FUZZY_MAX_PAT_LEN = 256`, `FUZZY_MAX_TEXT_LEN = 4096`
- `PCRE_NAME_MAX_LEN = 31`, `RE2_NAME_MAX_LEN = 31`

**MEDIUM finding (C1 from internal review)**: no boundary tests
verify that patterns at exactly MAX_* and MAX_*+1 either compile
cleanly or error with `*_E_TOO_LARGE`. Existing tests stay well
inside the limits; nobody's verified the edges. Step 6 adds a
per-engine boundary test group.

**No CRITICAL / HIGH findings.**
